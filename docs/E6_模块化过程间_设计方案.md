# E6 · 模块化过程间 APA 设计方案（草案，待评审）

> 目标：用**过程摘要（procedure summary as path expression）**替换当前
> `ForwardInterSummarySolver` 的"整程序 × 调用串上下文内联成单张图"路线，
> 从根上治掉 R1（非模块化展开）与 R2（全局稠密 O(N³) Kleene 闭包导致表达式爆炸）。
> 本文只做**设计**，不含实现。落码前需先锁定 §4 的决策点。

---

## 0. 问题复述（当前不可扩展的根因）

- **R1（非模块化）**：`ForwardInterSummarySolver` 把整个程序 × call-string 上下文
  内联成**一张**全局 `PathSummaryEquationGraph`；被 N 个上下文调用的过程展开 N 次。
  节点 ≈ 指令 × 上下文。
- **R2（主因，已文档记录）**：递归/大 SCC 用稠密 Floyd–Warshall Kleene 闭包
  `M[i][j]|=Col[i]·K*·Row[j]`（`PathSummaryEquationSolver.h:393-460`）跑在**程序级**
  指令图上 → 路径表达式尺寸天文级；与调用串 K 无关（K=0/1/2 全超时）。

**结论**：稀疏化（E4）只省内存不治 R2；治本必须换成模块化摘要构造。

---

## 1. 核心思想：过程摘要即路径表达式（functional / summary approach）

- 每个过程 P 求**一个** entry→exit 的路径表达式摘要 `S_P`，其原子取自
  `{ 原始 transfer 原子, SummaryCall(callee) }`。
- `S_P` 用**现有 intra 状态消元**（`StateEliminationSolver`）算**一次**，
  规模 = P 自身 CFG（本就 cap ≤300），**不再与上下文做笛卡尔积**。
- 调用指令在 P 的图里表示为 **`SummaryCall(callee)` 原子**（符号引用被调过程摘要，
  **不内联**）。
- 递归：把互递归过程团（call-graph SCC）里的摘要作为**一组互定义方程**，
  用 `PathSummaryEquationSolver` 求解——但**跑在 call-graph SCC 上（团内过程数 m，极小）**，
  star 只闭合"过程级递归"，而非指令级路径。

---

## 2. 算法（自底向上遍历 call-graph SCC）

> **构造期修正（2026-09-12，代码核实后）**：per-proc 摘要构造对递归/非递归
> **统一**，且**不需要 SCC 排序**——每过程只用自己的 CFG 建图求解，对同团过程的
> `SummaryCall` 是不透明占位。**递归的闭合是解释期定点（里程碑4）**，不进构造期。
> call-graph SCC（里程碑2）的产物：过程集喂 M3；反拓扑序 + `recursive` 标记喂 M4。

1. **建调用图 + SCC**（里程碑2，已完成）：得可达非 opaque 过程集与反拓扑序。
2. **逐过程建摘要**（里程碑3，统一处理）：对每个过程 P，用 **P 自身 CFG** 建
   `PathSummaryEquationGraph<n_t, atom_t>`（nodes = P 的指令）：
   - 普通边 → `RawNormal(edgeTransfer)` 原子；
   - 调用点 c（返回点 r、被调集 {g}）→ 见 §2a 调用边建模；
   - 用 `PathSummaryEquationSolver`（ForwardPath）求解 → 得 `S_P`（entry→exit）
     与 entry→每节点表达式（供 M4 出 IN facts）。
3. **存** `{P → S_P}` 与 `{(P,node) → entry→node expr}`，按过程为键（天然可缓存/增量）。

### 2a. 调用边建模（Decision B）
对照 `ForwardInterSummarySolver::discoverCallSuccessors`（内联被调体）：模块化版
**去掉内联边**，被调贡献换成符号 `SummaryCall`：
- 边 `c→r` 权重 = `RawNormal(bypass)`（+ 现有 `CallToRet` 原子）——本地 call-to-ret；
- 每个**非 opaque** callee g：再加平行边 `c→r` 权重 = `SummaryCall(c,g,r)`——被调路径
  （平行边由 solver 自动 union）；
- opaque callee（空 start/exit）：只留 bypass 边（与现跳过行为一致）。
语义与整程序求解器对齐，仅"内联"换"符号引用"。

## 3. 解释（IN/OUT facts）

- 求 P 内每条指令在入口事实 d 下的 IN：解释 P 的 entry→inst 局部路径表达式，
  遇 `SummaryCall(callee)` 原子 → 用 `callFlow` 进入、评估 `S_callee`、`returnFlow` 返回
  （复用 `InterSummaryTransferEvaluator` 的现成钩子）。
- **上下文敏感度**由此**从"构造期"下沉到"解释期"**（见 §4-D1）。

## 4. 关键决策点（落码前必须锁定）

**D1 · 精度目标 —— 已锁定：A（functional / 构造期上下文不敏感）** ✅
- 一过程一摘要。对**分配式**客户端（reachable/reaching_defs/liveness/affine）这是
  **Sharir–Pnueli 精确**（等价 call-string k=∞），**比现默认 K=2 更精确且可扩展**。
- 现默认 call-string 长度 = **K=2**（所有 inter 分析，`kDefault*CallStringLength=2`）。
  A 是 K=2 想逼近的那个精确解，故 A ⊒（不劣于）K=2；差异是 A 更精确，而非退化。
- **非分配式**（constant_prop/uninit）：functional 有精度警告 → 如实记录偏差
  （与 RQ1 律法门同一诚实口径），必要时该客户端单独说明或回退。

**D1-oracle · A 的验证策略（替换绑定 K=2 的旧预言）**
- **金标准**：`IFDS/Solver/IDESolver.h`（summary-edge reuse = functional 语义）作 reachable
  的 functional 参照。
- **廉价强回归**：在**非递归**或**递归深度 ≤ K** 的测试程序上，A **必须与现 K=2 worklist
  （`runInterElimReachable`）逐点相等**（此时 K=2 已精确）→ 现有
  `ForwardSummary*MatchesWorklist` 家族在这些程序上仍可作等值预言。
- **一般程序**：断言 A ⊑ worklist（A 不多报），并与 IDESolver 对拍精确性。

**D2 · 摘要粒度 —— 建议锁定**：entry→exit 单摘要（小）+ 解释期局部求 entry→inst。
 （拒绝 entry→每指令全摘要：大且与不内联初衷相悖。）

**D3 · 复用范围 —— 修正锁定（2026-09-12，代码核实）**：
 per-proc 摘要复用 **`PathSummaryEquationSolver<n_t, atom_t>`**（不是 intra
 `StateEliminationSolver`）。原因：`StateEliminationSolver`/`IntraEliminationSolverContext`
 硬绑 `PathExprFactory<transfer_t>`，原子来自 `edgeTransfer`，**无调用点概念、无法产
 `SummaryCall`**；而 `PathSummaryEquationSolver` 本就泛型于 `atom_t` 且用 star 处理
 intra 环，`ForwardInterSummarySolver` 已在用它——把作用域缩到单过程 CFG 即可。
 递归团用**解释期定点**（里程碑4）闭合，不在构造期建方程组。

**D4 · EAN 接入点 —— 建议锁定**：在**每过程摘要**上跑 EAN（小批、一过程一次、
 可按过程缓存），替代现在"整程序一大批"。天然契合 EAN 预算 + 摊还/增量。

**D5 · 里程碑 —— 建议锁定**（reachable 先行）：
 1. `SummaryCall` 原子种类（扩展 `InterSummaryTransferAtom` 一个 Kind）。
 2. call-graph 构建 + Tarjan SCC + 反拓扑序（自建，仓库无现成 CG-SCC 工具）。
 3. `ModularInterSummarySolver`（opt-in，与 `ForwardInterSummarySolver` 并存）：
    非递归单点用 intra 状态消元；递归团用 `PathSummaryEquationSolver`。
 4. 解释：复用 `InterSummaryTransferEvaluator` 钩子，`SummaryCall` → callFlow/评估
    S_callee/returnFlow。
 5. 对拍（D1-oracle）：非递归程序 == worklist；一般程序 vs IDESolver。
 6. 通过后推广到 reaching_defs/uninit/constant_prop/affine + 真实语料评测
    （inter Table VI/VII/RQ1 首次产出）。

---

## 5. 为什么这治 R1/R2

- **治 R1**：总工作量 = Σ(每过程 CFG) + call-graph SCC 求解（团内过程数），
  **线性于程序规模**，无上下文笛卡尔积。
- **治 R2**：稠密 O(N³) 只在**每过程 CFG（N≤cap）**与**call-graph SCC（m 个过程）**上跑，
  **绝不**在爆炸的"指令 × 上下文"全局图上跑；表达式尺寸按过程有界，
  递归 star 作用于**过程摘要**而非指令级路径。

---

## 6. 风险 / 开放问题

- **非分配式客户端**（constant_prop / uninit）：functional 近似有精度警告；
  可能需 Option B 或如实记录精度差（与 RQ1 律法门同一诚实口径）。
- **间接调用 / 多 callee**：`SummaryCall` over callee 集合 = 摘要之并（union）。
- **摘要作为真函数**的可表示性：APA 路径表达式解释对现支持客户端已提供此性质。
- **可评测性**：E6 打通后，inter 侧 Table VI/VII/RQ1 才**首次可能产出真实数据**
  （当前 path-summary 求解器几乎无程序完成）——这是 E6 的主要科研价值。

## 7. 与现有代码的关系（不破坏现状）

- 新增 `ModularInterSummarySolver`（与 `ForwardInterSummarySolver` 并存，opt-in），
  现全局求解器保留作对照基线。
- 复用：`StateEliminationSolver` / `PathExprFactory`（含本次 E1/E2 的 atom 去重）/
  `PathSummaryEquationSolver` / `InterSummaryTransferEvaluator` 钩子。
- 新增原子种类 `SummaryCall(callee)`（或扩展 `InterSummaryTransferAtom` 一个 Kind）。
